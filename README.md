# AIMORAFormats.jl

`AIMORAFormats.jl` is the public Julia owner for restricted YAML, canonical JSON, TOML, CSV/JSONL, migrations, source maps, diagnostics, and admitted import adapters. It contains no solver construction.

The current public surface admits bounded UTF-8 source documents, exact byte/line/column spans, deterministic diagnostics, solver-independent located format values, typed operation results, and an inert restricted-YAML parser and deterministic emitter. `parse_restricted_yaml` accepts block and flow mappings and sequences, quoted and plain strings, exact finite JSON-style numbers, lowercase booleans and null, and comments. It rejects duplicate keys, implicit legacy booleans, implicit dates, ambiguous or nonfinite numbers, tags, anchors, aliases, merge keys, directives, document markers, block scalars, tab indentation, invalid Unicode escapes, and configured resource-limit violations with source-located diagnostics.

`serialize_restricted_yaml` writes deterministic single-line flow YAML while preserving mapping insertion order and sequence order. Restricted YAML itself retains reserved project envelopes as ordinary inert mappings and strings. The separately invoked `parse_portable_reference`, `parse_reference_envelope`, `parse_artifact_envelope`, `parse_extends_envelope`, `parse_patch_envelope`, `parse_registered_function_identity`, and matching deterministic serializers validate the bounded portable syntax without resolving a target, opening a path, fetching a URI, applying inheritance or a patch, or loading a package function. Artifact paths are relative project-portable paths with exact lowercase SHA-256 and optional bounded size, schema, table, unit, ordering, and media-type metadata. Patch operation names are closed, targets use `$ref`, field paths use stable named segments, and registered functions pin a canonical package UUID and semantic version rather than source or an anonymous closure.

`parse_restricted_expression` and `parse_expression_envelope` admit exact numeric and Boolean literals, portable lexical variables, a closed pure-function family, arithmetic, comparisons, and Boolean operators into an inert typed syntax tree. `serialize_restricted_expression` emits deterministic fully parenthesized text with normalized exact numbers. Token, node, scalar, and recursive syntax depth are bounded before exhaustion. Assignment, mutation syntax, strings, commands, indexing, macros, blocks, control flow, reflection, process, filesystem, network, module-loading, unknown operators, and unknown functions are rejected with source-located diagnostics; there is deliberately no evaluator or callback in this package.

`resolve_project_documents` opens either one compact `*.aimora.yaml` file or an ordinary directory rooted by the exact name `project.aimora.yaml`. A strict replacement-style `{$include: path}` node expands project-relative YAML while retaining each included node's source span; every additional authoritative YAML document must have exactly one include owner. Resolution returns sorted source records, portable file roles, ignored derived locations, source and canonical-resolved SHA-256 identities, and the fully inline inert root. Optional `checksums.sha256` entries and every `$artifact` declaration are verified against contained regular files. Path traversal, absolute paths, URI/glob paths, symlinks, case/Unicode collisions, include cycles, duplicate/orphan ownership, unknown files, derived-file promotion, changed checksums, and configured file/byte/hash limits fail deterministically. `serialize_compact_project` writes the resolved root only when no separate lock, script, SVG, or other authoritative resource would be lost.

Project resolution is data-only: Julia scripts, plugin locks, symbol resources, imports, results, and `.aimora-cache/` are never executed or parsed as project YAML. Results and cache directories may be absent or deleted without preventing open and do not enter source or resolved hashes. The admitted package is a directory or compact text file, not a ZIP-like `.aimora` archive. Import adapters remain unavailable until their executable packets pass; repository presence does not imply support for them.

`parse_json` admits exact source-located JSON with arbitrary-precision integers and decimals while rejecting comments, duplicate keys, nonfinite or ambiguous numbers, invalid escapes, invalid Unicode, trailing data, and resource-limit violations. `serialize_canonical_json` emits UTF-8 with mapping keys ordered by Unicode scalar value, sequence order unchanged, shortest controlled string escapes, normalized exact integers, and normalized decimals as `coefficient` followed by lowercase `e` and the base-ten exponent. Decimal zero is `0e0`, negative zero is `-0e0`, and neither is collapsed into integer zero. `canonical_json_sha256` returns the lowercase SHA-256 of those exact bytes; presentation order, YAML comments, whitespace, and source spans therefore do not own content identity. This is AIMORA's exact canonicalization profile rather than an IEEE-754 JSON Canonicalization Scheme implementation.

`compile_structural_schema` admits a strict, source-located JSON Schema 2020-12 structural subset with required root `$schema` and `$id`, explicit types and bounds, object and array constraints, enums and constants, compositions and conditionals, annotations, and bounded local `#/$defs/name` references. Unknown keywords, external references, nested identities, malformed or contradictory declarations, recursive evaluation cycles, and schema-lock identity or SHA-256 mismatches fail explicitly. `StructuralSchemaIdentity`, `SchemaVersionPolicy`, `schema_compatibility`, and `StructuralSchemaRegistry` keep lock IDs, schema URIs, semantic versions, backward-reader promises, exact compiled schemas, and migration availability distinct.

`MigrationGraph`, `plan_migration`, and `migrate_format_document` provide deterministic declarative upgrades and only explicitly invertible downgrades between registered schema versions. A migration step may assert an existing value, rename a mapping key, move an existing value, set the exact schema-version field, or remove a value with mandatory loss accounting; it cannot call Julia, fabricate engineering data, access resources, or execute an arbitrary callback. Migration validates the source and target schemas, retains source-to-result paths and spans, records step provenance, changes, losses, and canonical hashes, supports report-equivalent dry runs, and returns no document after any failed operation or validation.

`parse_format_lock` and `serialize_format_lock` own deterministic `aimora-lock-v1` TOML for schema, catalog, plugin, import, and automation dependency families. Every entry pins an exact version, revision hash, SHA-256, licence, bounded compatibility range, portable source, trust class, provenance, permissions, entrypoint/environment where executable code is declared, and bounded resource policy. Unknown fields, versions, families, floating compatibility, malformed or conflicting identities, credentials, absolute/local paths, and family/trust mismatches fail with source-located diagnostics. `inspect_julia_environment` hashes and inspects inert `Project.toml` and `Manifest.toml` text and their direct dependency pins; it never instantiates an environment, downloads a package, grants a permission, or loads or executes Julia code.

`BulkTableSchema` declares ordered scalar columns, one stable string or integer row identity, nullable fields, and inert unit/basis labels. `parse_delimited_table` and `serialize_delimited_table` implement explicit UTF-8 CSV or TSV policies for delimiters, double-quote escaping, required or absent headers, null tokens, quote modes, and LF or CRLF output. `parse_json_lines` and `serialize_json_lines` provide the equivalent newline-delimited canonical-JSON object surface. Strings, arbitrary-precision integers, exact decimals, lowercase booleans, and null remain distinct: dates, engineering units, identifiers, and alternate boolean spellings are never inferred. Every collected row and cell retains a source span, while duplicate headers, inconsistent widths, duplicate row identities, invalid scalar kinds, malformed quoting, invalid UTF-8, and configured byte/scalar/collection limits produce typed diagnostics.

`stream_delimited_rows` and `stream_json_lines` read one bounded record at a time from an `IO`, emit source-located rows to a Boolean consumer, retain only the current record plus a bounded identity set, and stop without consuming the remainder when the consumer returns `false`. Their summaries report records, emitted rows, consumed bytes, and early termination. These readers do not construct project assets, infer engineering semantics, execute code, or retain an unbounded result table.

`ImportAdapterIdentity` and `ImportAdapterRegistry` declare exact source format/version ownership backed by one or more immutable fixture hashes; they contain no callback or loader. `compile_generic_table_import` turns a typed `ParsedBulkTable` into source semantic records and inert create/field-assignment operations. Every source cell receives exactly one mapped, ignored-with-justification, unsupported, or rejected accounting record with its original file, row/cell span, raw row identity, unit, and basis. Explicit null omission, assumptions, unsupported/rejected losses, reconciled totals, applicability, the original source hash, adapter version, and a reproducible plan hash remain inspectable. Missing, duplicate, unknown, or conflicting mappings fail before a plan exists, while unsupported and rejected meanings produce a complete non-applicable report rather than silent partial conversion. Applying these operations as canonical project commands belongs to `AIMORAProject.jl`; this package constructs no project or solver object.

`read_aimora_project_v1`, `read_aimora_asset_csv`, `read_aimora_catalog_entry_v1`, and `read_aimora_cases_catalog_v2` migrate the four current native AIMORA text surfaces into that same inert plan/report contract. They preserve exact source hashes and account for missing asset content, externally supplied CSV schemas, arbitrary dictionary parameters, implicit units, absent locks and hashes, unknown fields and versions, and optionally verified case-resource inventories without loading a project, solver, Julia entrypoint, or private dependency. Run `julia --project=. examples/native_migrations.jl` for a public data-only example.
